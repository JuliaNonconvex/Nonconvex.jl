NonconvexCore

Description

NonconvexCore.jl is the modelling and automatic differentiation foundation of the JuliaNonconvex ecosystem: every solver package — Ipopt, NLopt, MMA, Percival, Metaheuristics, the semidefinite and augmented Lagrangian methods, the Bayesian optimizers and the reliability-analysis tools — builds on the same model types, constraint machinery, derivative rules and solver interface.

Models are declared with Model or DictModel: variables with box and integrality bounds, an objective and any mix of equality, inequality, interval and semidefinite constraints. As of NonconvexCore 2.3 there is also a unified function-in-set framework — EqualTo, LessThan, GreaterThan, Interval, PSDCone, ChanceSet and SetProduct — with add_set_constraint!, add_set_variable! and add_chance_constraint!, the same interface consumed by the augmented Lagrangian (NonconvexAugLagLab) and semidefinite (NonconvexSemidefinite) meta-algorithms.

Gradients, Jacobians and Hessians come from the Zygote and ForwardDiff backends behind a common ADTypes interface: set_ad_backend! and get_ad_backend select the package-wide backend, prepare_gradient prepares derivative evaluations explicitly, diffy attaches custom derivatives to plain functions, LazyJacobian defers the evaluation of expensive Jacobians and TraceFunction records function-call histories. Symbolic models can be differentiated with Symbolics (symbolify) or converted from a JuMP model (DictModel(jump_model), see JuMP models).

Every solver advertises which model features it supports through the solver capability system, and declares the convergence criteria it understands; getmin, getmax, getobjective and the other model queries give solver-independent access to a model's state, and set_violation measures the violation of a function-in-set constraint.

See Models for model types, variables and constraints, JuMP models for the JuMP conversion path, AD backends and Sparse Jacobians and Hessians for the derivative machinery, Gradients, Jacobians and Hessians for user-defined derivatives, ChainRules in ForwardDiff and gradient-call history, Function modifiers for diffy, lazy Jacobians and call tracing, Symbolic differentiation for the Symbolics interface, Solver capabilities for the capability system, Convergence criteria for the criteria interface, Model queries for the query API, Optimization result for the fields of the returned result and Docstrings for the full API reference.
