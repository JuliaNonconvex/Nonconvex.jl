NonconvexCore.NonconvexCore — Module
NonconvexCore

The modelling and automatic differentiation core of the Nonconvex ecosystem: the optimization model types, objective and constraint functions, the differentiation machinery shared by the solver packages, and the solver capability system. See the Introduction for an overview.

NonconvexCore.ConstraintCapabilities — Type
ConstraintCapabilities(; linear_eq = missing, nonlinear_eq = missing,
                         linear_ineq = missing, nonlinear_ineq = missing,
                         sd = missing, box = missing,
                         continuous = missing, binary = missing,
                         integer = missing, infinite_bounds = missing)

Declares which constraint/variable features an optimizer supports:

  • linear_eq: linear equality constraints,
  • nonlinear_eq: nonlinear equality constraints,
  • linear_ineq: linear inequality constraints,
  • nonlinear_ineq: nonlinear inequality constraints,
  • linear_sd: linear semidefinite constraints,
  • nonlinear_sd: nonlinear semidefinite constraints,
  • box: finite variable bounds,
  • continuous: continuous variables,
  • binary: binary (0/1) variables,
  • integer: integer (non-binary) variables,
  • infinite_bounds: variables with infinite (unbounded) bounds.

Each field is one of true (supported), false (not supported) or missing (unknown/not declared). A solver that returns nothing from solver_capabilities declares nothing at all.

NonconvexCore.GenericCriteria — Type
GenericCriteria

This is a generic convergence criteria that uses:

  1. The maximum change in the solution, Δx,
  2. The change in the objective value, Δf, and
  3. The change percentage in the objective value, Δf, and
  4. The maximum infeasibility infeas.

to assess convergence. More details are given in assess_convergence!.

NonconvexCore.IpoptCriteria — Type
IpoptCriteria

This convergence criteria uses a scaled version of the Karush-Kuhn-Tucker (KKT) residual and maximum infeasibility to assess convergence. This scaled KKT residual is used in the IPOPT nonlinear programming solver as explained in this paper. More details are given in assess_convergence!.

NonconvexCore.Model — Type
struct Model <: AbstractModel
    objective::Objective
    eq_constraints::VectorOfFunctions
    ineq_constraints::VectorOfFunctions
    box_min::AbstractVector
    box_max::AbstractVector
    init::AbstractVector
    integer::AbstractVector
end

The Model structs stores information about the nonlinear optimization problem.

  • objective: the objective function of the problem of type Objective.
  • eq_constraints: the equality constraints of the problem of type VectorOfFunctions. Each function in ineq_constraints can be an instance of IneqConstraint or AbstractFunction. If the function is not an IneqConstraint, its right-hand-side bound is assumed to be 0.
  • ineq_constraints: the inequality constraints of the problem of type VectorOfFunctions. Each function in ineq_constraints can be an instance of IneqConstraint or AbstractFunction. If the function is not an IneqConstraint, its right-hand-side bound is assumed to be 0.
  • sd_constraints: a list of matrix-valued functions which must be positive semidefinite at any feasible solution.

NonconvexCore.ScaledKKTCriteria — Type
ScaledKKTCriteria

This convergence criteria uses another scaled version of the Karush-Kuhn-Tucker (KKT) residual and maximum infeasibility to assess convergence. In particular if the objective was scaled by a factor m, the KKT residual will be scaled down by a factor max(m, 1/m). This scaling was found to make the convergence criteria less sensitive to scale compared to using the traditional KKT residual. More details are given in assess_convergence!.

NonconvexCore.Tolerance — Type
Tolerance

A struct specifying the different tolerances used to assess the convergence of the algorithms. The following are the fields of Tolerance:

  • x: the tolerance for Δx in ConvergenceState. x_converged will be true if Δx is less than the x tolerance in Tolerance. This is used to assess convergence when the GenericCriteria is used as the convergence criteria.
  • fabs: the tolerance for Δf in ConvergenceState. f_converged will be true if Δf is less than the fabs tolerance in Tolerance. This is used to assess convergence when the GenericCriteria is used as the convergence criteria.
  • frel: the tolerance for relΔf in ConvergenceState. f_converged will be true if relΔf is less than the frel tolerance in Tolerance. This is used to assess convergence when the GenericCriteria is used as the convergence criteria.
  • kkt: the KKT tolerance. kkt_converged in ConvergenceState will be true if the kkt_residual is less than the KKT tolerance. And ipopt_converged in ConvergenceState will be true if ipopt_residual is less than the KKT tolerance. This is used to assess convergence when the KKTCriteria, the ScaledKKTCriteria or IpoptCriteria criteria is used as the convergence criteria.
  • infeas: the maximum infeasibility tolerance. infeas_converged in ConvergenceState will be true if the maximum infeasibility is less than the infeasibility tolerance. This is used to assess convergence regardless of the convergence criteria used.

For more on convergence criteria, see GenericCriteria, KKTCriteria, ScaledKKTCriteria and IpoptCriteria.

NonconvexCore.checksubproblem! — Method
checksubproblem!(model::VecModel, optimizer; assumed = nothing,
                 hint = "", context = "the model")

Validates the features present in model against solver_capabilities of optimizer. Semantics per present feature:

  • declared true → pass;
  • declared false → ArgumentError naming the solver, the feature and a hint on how to work around it;
  • undeclared (missing or no declaration at all) → ArgumentError requiring the solver to declare the capability via solver_capabilities (strict-by-default: no opt-in).

Keyword arguments:

  • assumed: optional ConstraintCapabilities to use instead of querying the solver (for meta-algorithms that override their sub-solver's declaration),
  • hint: extra text appended to error messages,
  • context: description of the model used in error messages.

NonconvexCore.optimize — Method
optimize(
    model::AbstractModel,
    optimizer::AbstractOptimizer,
    x0;
    options,
    convcriteria::ConvergenceCriteria = KKTCriteria(),
    callback = NoCallback(),
    kwargs...,
)

Optimizes model using the algorithm optimizer (a solver package's AbstractOptimizer instance, e.g. IpoptAlg() from NonconvexIpopt). x0 is the initial solution, and defaults to getinit when omitted. The keyword arguments are:

  • options: the solver options object of the selected algorithm.
  • convcriteria: an instance of ConvergenceCriteria that specifies the convergence criteria of the algorithm.
  • callback: a function that is called on solution in every iteration of the algorithm. This can be used to store information about the optimization process.

The model is validated against the solver's declared capabilities with checksubproblem! before the optimization starts, and the returned result contains the minimum and minimizer fields (see Optimization result).

NonconvexCore.sparse_jacobian — Function

Returns the structurally sparse Jacobian of f at x as a SparseMatrixCSC. NonconvexCore.ConvergenceState — Type
ConvergenceState

A struct that summarizes the convergence state of a solution. The fields in this struct are:

  • Δx: the infinity norm of the change in the solution x.
  • Δf: the change in the objective value f.
  • relΔf: the ratio of change in the objective value f.
  • kkt_residual: the Karush-Kuhn-Tucker (KKT) residual of the solution. If ScaledKKTCriteria is used instead of KKTCriteria, the kkt_residual will be divided by a factor.
  • ipopt_residual: the modified KKT residual used in the IPOPT solver.
  • infeas: maximum infeasibility amount. This is 0 if the solution is feasible.
  • x_converged: true if Δx is less than the x tolerance in Tolerance.
  • fabs_converged: true if Δf is less than the f tolerance in Tolerance.
  • frel_converged: true if relΔf is less than the f tolerance in Tolerance.
  • kkt_converged: true if the kkt_residual is less than the KKT tolerance in Tolerance.
  • ipopt_converged: true if the ipopt_residual is less than the KKT tolerance in Tolerance.
  • infeas_converged: true if infeas is less than the infeasibility tolerance in Tolerance.
  • f_increased: true if the objective value of the current solution is higher than that of the previous solution.
  • converged: true if the solution satisfies the convergence criteria of choice. See ConvergenceCriteria for more on the different convergence criteria available.

NonconvexCore.JuMPEvaluator — Type
JuMPEvaluator

A single MathOptInterface Nonlinear evaluator over an entire JuMP model converted into a NonconvexCore model. The objective and every constraint are expressions of one MOI.Nonlinear.Model, so shared subexpressions are evaluated once per pass, and the whole Jacobian and Lagrangian Hessian come from single evaluator calls.

The constraints are keyed by their ConstraintIndex, because neither the JuMP constraint iteration order nor the evaluator row order is meaningful; the evaluator's own row order is recovered from ordered_constraints. Converted rows are exposed inequality-first (sorted by constraint index), then equalities (also sorted by constraint index). Inequality row k has value sign * f_k(x) + shift (Nonconvex convention: feasible when <= 0); equality row k has value f_k(x) + shift (feasible when 0). The objective is objective_sign * f_obj(x).

NonconvexCore.@params — Macro
@params struct_def

A macro that changes all fields' types to type parameters while respecting the type bounds specificied by the user. For example:

@params struct MyType{T}
    f1::T
    f2::AbstractVector{T}
    f3::AbstractVector{<:Real}
    f4
end

will define:

struct MyType{T, T1 <: T, T2 <: AbstractVector{T}, T3 <: AbstractVector{<:Real}, T4}
    f1::T1
    f2::T2
    f3::T3
    f4::T4
end

The default non-parameteric constructor, e.g. MyType(f1, f2, f3, f4), will always work if all the type parameters used in the type header are used in the field types. Using a type parameter in the type header that is not used in the field types such as:

struct MyType{T}
    f1
    f2
end

is not recommended.

NonconvexCore.GenericResult — Type
GenericResult

A summary result struct returned by optimize, including following fields:

  • optimizer: the optimization algorithm used
  • initial_x: the initial primal solution
  • minimizer: the best solution found
  • minimum: the optimal value
  • iter: number of inner iterations run
  • maxiter_reached: true if the algorithm stopped due to reaching the maximum number of iterations
  • tol: an instance of Tolerance that specifies the convergence tolerances
  • convstate: an instance of ConvergenceCriteria that summarizes the convergence state of the best solution found
  • fcalls: the number of times the objective and constraint functions were called during the optimization

Returns a callable that evaluates f and whose derivatives are computed by the differentiation backend backend (an ADTypes backend, defaulting to the package-wide backend), prepared eagerly at the representative point x. NonconvexCore.FlattenedFunction — Type
FlattenedFunction

A callable that evaluates the wrapped function f on the structure rebuilt by unflattenx from a flat vector, and flattens the output. The raw function and the input unflattening are exposed via getrawfunction and getinputunflatten so that solvers can evaluate all model functions against a single reconstructed structure per point.

NonconvexCore.DEFAULT_AD_BACKEND — Constant
DEFAULT_AD_BACKEND

The automatic differentiation backend used by default wherever NonconvexCore computes derivatives, e.g. in value_gradient, value_jacobian, sparse_jacobian and the solver-facing derivative evaluators. It is initially ADTypes.AutoZygote(), whose ChainRules-based design supports arbitrary argument types (dictionaries, structs, arrays) through the model-flattening machinery. Change it with set_ad_backend!, or pass a backend explicitly to the functions above.
