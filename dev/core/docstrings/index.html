NonconvexCore.NonconvexCore — Module
NonconvexCore

The modelling and automatic differentiation core of the Nonconvex ecosystem: the optimization model types, objective and constraint functions, the differentiation machinery shared by the solver packages, and the solver capability system. See the Introduction for an overview.

NonconvexCore.ChanceSet — Type
ChanceSet(set, scenarios; epsilon = 0.05, kappa = 10.0)

A probabilistic constraint set: a function f(x, ξ) lies in the inner set with a certain probability — P_ξ[f(x, ξ) ∈ set] ≥ 1 - epsilon, where the exceedance probability is estimated by a smooth (tanh) sample average of the exceedance indicator with sharpness kappa, which is differentiable and exactly zero on feasible scenarios.

The scenario batch scenarios (a vector of ξ values) is supplied by the caller: NonconvexCore defines the constraint and evaluates it over the given batch, it does not draw random scenarios — the RNG (and the seed) stays with the caller. With epsilon = Zero() the constraint is deterministic and scenarios is ignored (f is evaluated once with ξ = nothing).

When the inner set is a SetProduct, epsilon can be a vector of probabilities, one per output — each output lies in its own set with its own probability (P[fⱼ(x, ξ) ∈ Sⱼ] ≥ 1 - εⱼ), all sharing the same scenario batch.

epsilon = Zero() expresses a deterministic constraint: the single evaluation is exact (no smoothing).

Use it in the function-in-set form — the FunctionInSet evaluation iterates the scenario batch and returns the batch of inner-set values — or through add_chance_constraint!:

ξs = [rand(StableRNG(1), dist) for _ in 1:1000]
add_set_constraint!(m, FunctionInSet((x, ξ) -> x[1] + ξ,
                                     ChanceSet(LessThan(1.0), ξs; epsilon = 0.1)))
NonconvexCore.ConstraintCapabilities — Type
ConstraintCapabilities(; linear_eq = missing, nonlinear_eq = missing,
                         linear_ineq = missing, nonlinear_ineq = missing,
                         linear_sd = missing, nonlinear_sd = missing,
                         sets_eq = false, sets_ineq = false,
                         sets_sd = false, sets_simplex = false,
                         sets_product = false, variable_sets_sd = false,
                         variable_sets_simplex = false, box = missing,
                         continuous = missing, binary = missing,
                         integer = missing, infinite_bounds = missing)

Declares which constraint/variable features an optimizer supports:

  • linear_eq: linear equality constraints,
  • nonlinear_eq: nonlinear equality constraints,
  • linear_ineq: linear inequality constraints,
  • nonlinear_ineq: nonlinear inequality constraints,
  • linear_sd: linear semidefinite constraints,
  • nonlinear_sd: nonlinear semidefinite constraints,
  • sets_eq: function-in-set equality constraints (EqualTo, Zeros, defaults to false — not supported),
  • sets_ineq: function-in-set inequality/order constraints (LessThan, GreaterThan, Interval, Nonnegatives, Nonpositives; defaults to false),
  • sets_sd: function-in-set semidefinite constraints (PSDCone; defaults to false),
  • sets_simplex: function-in-set simplex constraints (Simplex; defaults to false),
  • sets_product: function-in-set product constraints (SetProduct; defaults to false),
  • sets_chance: probabilistic (chance) constraints (ChanceSet, including per-output probabilities and deterministic Zero() constraints; defaults to false),
  • variable_sets_sd: variables defined as PSDCone blocks (semidefinite matrix variables; defaults to false),
  • variable_sets_simplex: variables defined as Simplex blocks (defaults to false),
  • box: finite variable bounds,
  • continuous: continuous variables,
  • binary: binary (0/1) variables,
  • integer: integer (non-binary) variables,
  • infinite_bounds: variables with infinite (unbounded) bounds.

Each field is one of true (supported), false (not supported) or missing (unknown/not declared). A solver that returns nothing from solver_capabilities declares nothing at all.

NonconvexCore.CustomGradFunction — Type
CustomGradFunction(f, g)

Wraps the function f so that its gradient (or Jacobian, for vector-valued f) is computed by the user-supplied function g instead of automatic differentiation.

NonconvexCore.CustomHessianFunction — Type
CustomHessianFunction(f, g, h; hvp = false)

Wraps the function f so that its gradient (or Jacobian, for vector-valued f) is computed by g and its Hessian by h (or, with hvp = true, by a Hessian-vector product operator).

For a scalar-valued f, h(x) returns the Hessian matrix (or, with hvp = true, h(x, v) returns the Hessian-vector product ∇²f(x)·v).

For a vector-valued f (e.g. a block equality constraint), pass hvp = true and let h(x, v) return the per-component Hessian-vector products: an array shaped like J(x) * v whose i-th row is ∇²fᵢ(x)·v. The weighted Lagrangian Hessian Σ μᵢ∇²fᵢ(x) is then assembled from those products, which is all the second-order solvers need from a vector-valued constraint.

NonconvexCore.DictModel — Type
DictModel(obj = nothing)

An AbstractModel whose variables are named: each variable has a Symbol or String key and arbitrary structured values, collected in an OrderedDict. The JuMP model conversion is provided by the NonconvexCoreJuMPExt extension when JuMP is loaded.

NonconvexCore.EqualTo — Type
EqualTo(value)

The set of functions equal to value. value can be a scalar (one output) or a vector (several outputs, all pinned to the corresponding entries of value).

NonconvexCore.EqualitySet — Type
EqualitySet(value)  (alias of [`EqualTo`](@ref))

The default set of the classical equality-constraint syntax: the set of functions f with f(x) = value. add_eq_constraint!(m, f, s) is f ∈ EqualitySet(s) under the hood.

NonconvexCore.FunctionInSet — Type
FunctionInSet(f, set; flags = Set{Symbol}())

A constraint of the form "the function f lies in the set set", i.e. f(x) ∈ set. f is evaluated once per call and its output is checked against set:

  • EqualTo(value)/LessThan(upper)/GreaterThan(lower)/Interval(lo, up) accept scalar or vector-valued f;
  • PSDCone(n) accepts a matrix-valued f (the matrix must be positive semidefinite);
  • SetProduct(s₁, …, sₖ) accepts a k-tuple output, routing each component to its own set — a single evaluation can therefore feed e.g. an inequality and a semidefinite constraint at once, reusing the computation inside f.

flags labels the constraint: meta-algorithms select constraints by label, e.g. chordal_transform(m, patterns; labels = [:chordal]) (from NonconvexSemidefinite.jl) and AugLagOptions(relaxed = RelaxConstraintSelection(labels = [:relax])).

Add one to a model with add_set_constraint!.

NonconvexCore.GenericCriteria — Type
GenericCriteria

This is a generic convergence criteria that uses:

  1. The maximum change in the solution, Δx,
  2. The change in the objective value, Δf, and
  3. The change percentage in the objective value, Δf, and
  4. The maximum infeasibility infeas.

to assess convergence. More details are given in assess_convergence!.

NonconvexCore.LinearFunction — Type
LinearFunction(A, b = nothing)

A first-class linear (affine) function x ↦ A x + b (or A x when b is nothing), with getdim equal to the number of rows of A. Recognized as such by the model layer — solvers classify the corresponding constraints as linear exactly and model transforms (nullspace_transform, unconstrained_transform) can act on them structurally.

Combine with a set for the function-in-set form:

add_linear_constraint!(m, A, LessThan(ub))     # A x ≤ ub
add_linear_constraint!(m, A, EqualTo(rhs))     # A x = rhs
NonconvexCore.Model — Type
struct Model <: AbstractModel
    objective::Objective
    eq_constraints::VectorOfFunctions
    ineq_constraints::VectorOfFunctions
    box_min::AbstractVector
    box_max::AbstractVector
    init::AbstractVector
    integer::AbstractVector
end

The Model structs stores information about the nonlinear optimization problem.

  • objective: the objective function of the problem of type Objective.
  • eq_constraints: the equality constraints of the problem of type VectorOfFunctions. Each function in ineq_constraints can be an instance of IneqConstraint or AbstractFunction. If the function is not an IneqConstraint, its right-hand-side bound is assumed to be 0.
  • ineq_constraints: the inequality constraints of the problem of type VectorOfFunctions. Each function in ineq_constraints can be an instance of IneqConstraint or AbstractFunction. If the function is not an IneqConstraint, its right-hand-side bound is assumed to be 0.
  • sd_constraints: a list of matrix-valued functions which must be positive semidefinite at any feasible solution.

NonconvexCore.PSDCone — Type
PSDCone(n)

The cone of positive semidefinite n × n symmetric matrices. The function evaluated against it must return a matrix; a variable block registered with add_set_variable! is an n × n semidefinite matrix variable. The chordal-decomposition and semidefinite algorithms live in NonconvexSemidefinite.jl; the cone type itself is defined here so that all sets share one home.

NonconvexCore.Reals — Type
Reals(dim)

The whole space ℝ^dim: the general default vector variable set, giving dim free (unbounded) variables. The plain addvar! box API falls back on the Interval vector set.

NonconvexCore.ScaledKKTCriteria — Type
ScaledKKTCriteria

This convergence criteria uses another scaled version of the Karush-Kuhn-Tucker (KKT) residual and maximum infeasibility to assess convergence. In particular if the objective was scaled by a factor m, the KKT residual will be scaled down by a factor max(m, 1/m). This scaling was found to make the convergence criteria less sensitive to scale compared to using the traditional KKT residual. More details are given in assess_convergence!.

NonconvexCore.SetProduct — Type
SetProduct(sets...)
SetProduct(sets::AbstractVector{<:AbstractSet})

The product of sets. A single function x -> (v₁, v₂, …, vₖ) evaluated against SetProduct(s₁, s₂, …, sₖ) lies in the set when vᵢ lies in sᵢ for every component. This is the construct that lets one expensive computation (e.g. a finite-element displacement solve) feed several constraints of different kinds — scalar, vector and matrix-valued — with a single function evaluation.

Components can be composed freely: SetProduct(Simplex(4), Simplex(4)) is a pair of simplexes, and products may be nested. Semidefinite components (PSDCone) compose the same way.

NonconvexCore.Simplex — Type
Simplex(dim)

The probability simplex {x ∈ ℝ^dim : x ≥ 0, Σᵢ xᵢ = 1}.

NonconvexCore.StanSimplex — Type
StanSimplex(n)

The Stan (MCMC) simplex transform, as a TransformVariables transformation: the n - 1 unconstrained reals z map to the open simplex via the log-ratio/softmax bijection y = softmax([z; 0]) (the last component pinned to zero log-weight — Stan's current simplex transform), with inverse zᵢ = log(yᵢ / yₙ). TransformVariables' own UnitSimplex uses the stick-breaking construction instead, which is a different parameterization; unconstrained_transform uses this one. The log-Jacobian correction is not tracked (the transform is intended for optimization re-parameterization, not density computation).

NonconvexCore.Tolerance — Type
Tolerance

A struct specifying the different tolerances used to assess the convergence of the algorithms. The following are the fields of Tolerance:

  • x: the tolerance for Δx in ConvergenceState. x_converged will be true if Δx is less than the x tolerance in Tolerance. This is used to assess convergence when the GenericCriteria is used as the convergence criteria.
  • fabs: the tolerance for Δf in ConvergenceState. f_converged will be true if Δf is less than the fabs tolerance in Tolerance. This is used to assess convergence when the GenericCriteria is used as the convergence criteria.
  • frel: the tolerance for relΔf in ConvergenceState. f_converged will be true if relΔf is less than the frel tolerance in Tolerance. This is used to assess convergence when the GenericCriteria is used as the convergence criteria.
  • kkt: the KKT tolerance. kkt_converged in ConvergenceState will be true if the kkt_residual is less than the KKT tolerance. And ipopt_converged in ConvergenceState will be true if ipopt_residual is less than the KKT tolerance. This is used to assess convergence when the KKTCriteria, the ScaledKKTCriteria or IpoptCriteria criteria is used as the convergence criteria.
  • infeas: the maximum infeasibility tolerance. infeas_converged in ConvergenceState will be true if the maximum infeasibility is less than the infeasibility tolerance. This is used to assess convergence regardless of the convergence criteria used.

For more on convergence criteria, see GenericCriteria, KKTCriteria, ScaledKKTCriteria and IpoptCriteria.

NonconvexCore.TraceFunction — Type
TraceFunction(f; on_call = ..., on_grad = ...)

Wraps f and records a trace of where it is evaluated (on the function call and/or on gradient evaluations), for debugging which part of a model calls a function during optimization.

NonconvexCore.VariableInSet — Type
VariableInSet(set, range; flags = Set{Symbol}())

A block of decision variables constrained to lie in the set set: the entries of the (flattened) variable vector in range must form a value in set. Created by add_set_variable! and addvar!; a PSDCone(n) block is an n × n semidefinite matrix variable, a Simplex(n) block is a probability simplex variable, and the order sets give bounded or fixed variable blocks. flags labels the block for meta-algorithm selection.

NonconvexCore.VectorSet — Type
abstract type VectorSet <: AbstractSet end

A set on vectors of ℝ^dim: the domain of the order sets (EqualTo, LessThan, GreaterThan, Interval), the sign cones (Nonnegatives, Nonpositives, Zeros), Simplex and the general default Reals.

NonconvexCore.Workspace — Type
Workspace

Abstract Workspace, which is a struct that stores states and information needed for optimization process. Implementation depends on specific algorithm.

NonconvexCore.Zero — Type
Zero()

A special value for the probability input of a ChanceSet: with epsilon = Zero() the constraint is deterministic — the function is evaluated exactly once with ξ = nothing and must lie in the inner set (probability one). The scenario batch is ignored.

NonconvexCore.Zeros — Type
Zeros(dim)

The set consisting of the zero vector of length dim.

NonconvexCore.add_chance_constraint! — Method
add_chance_constraint!(m::AbstractModel, c::AbstractConstraint, scenarios;
    epsilon = 0.05, kappa = 10.0)
add_chance_constraint!(m::AbstractModel, f, scenarios, set::AbstractSet;
    epsilon = 0.05, kappa = 10.0, flags = Set{Symbol}())

Adds the probabilistic constraint P_ξ[f(x, ξ) ∈ set] ≥ 1 - epsilon to the model m in place. Any existing constraint type can be turned probabilistic: pass a classical constraint (IneqConstraint, EqConstraint, SDConstraint) or a FunctionInSet whose function takes the decision vector x and a random scenario ξ; the bound is the constraint's own set. Equivalently, pass the function and the bound directly as a set (LessThan, Interval, PSDCone from NonconvexSemidefinite.jl, …) together with the scenario batch scenarios (a vector of ξ values drawn by the caller with the RNG of its choice — NonconvexCore does not sample).

The exceedance probability is estimated by a smooth (tanh) sample average of the indicator with sharpness kappa (see ChanceSet), making the constraint differentiable. With a SetProduct bound, epsilon can be a vector of probabilities, one per output, each output sharing the same scenario batch; epsilon = Zero() expresses a deterministic constraint. Requires the sets_chance solver capability.

NonconvexCore.add_epigraph_variable! — Method
add_epigraph_variable!(m::AbstractModel; margin = 1.0, t_lb = -Inf, t_ub = Inf)

Reformulates the model in place with the epigraph trick: a new scalar variable t (appended to the variables, initialized at objective(init) + margin) becomes the objective, and the former objective f is dropped from the objective slot so it can be constrained by the caller — typically inside a SetProduct component f(x) - t, so that one function evaluation feeds the objective bound and other constraints at once. Returns the VariableInSet block of t.

epigraph! is the fully automatic variant that also adds the epigraph inequality f(x) - t ≤ 0 as a set constraint.

NonconvexCore.add_set_constraint! — Method
add_set_constraint!(m::AbstractModel, f::Function, set::AbstractSet)
add_set_constraint!(m::AbstractModel, c::FunctionInSet)

Adds the function-in-set constraint f(x) ∈ set to the model m in place. f must return a value whose shape matches set: a scalar or vector for the order sets, a matrix for a semidefinite cone (PSDCone, provided by NonconvexSemidefinite.jl), or a tuple with one entry per component of a SetProduct. The output shape is validated by evaluating f once at the model's initial point.

Solvers must declare support for function-in-set constraints via the sets capability of ConstraintCapabilities; AugLagAlg from NonconvexAugLagLab is the reference implementation.

NonconvexCore.add_set_variable! — Method
add_set_variable!(m::Model, set::AbstractSet; init = nothing, integer = false)

Adds a block of decision variables constrained to lie in the set set, in place. The block is registered as a VariableInSet (returned): PSDCone(n) introduces an n × n semidefinite matrix variable, Simplex(n) a probability simplex variable, the order sets bounded/fixed blocks, and SetProduct a concatenation of blocks. The cone parts the box cannot express (PSD-ness, the simplex sum) become synthetic set constraints at model conversion, so solvers handle variable sets exactly like FunctionInSet constraints — declare the sets and variable_sets capabilities.

NonconvexCore.addvar! — Function
addvar!(model::AbstractModel, lb::Number, ub::Number; init = lb, integer = false)

Adds a new variable to model with lower and upper bounds lb and ub, initial value init and integer = true if the variable is integer.

NonconvexCore.addvar! — Method
addvar!(m::Model, lb, ub; init=deepcopy(lb), integer=false)

Adds a decision variable with lower bound(s) lb and upper bound(s) ub to the model m in place, optionally with an initial value init and an integer flag. lb and ub can be scalars or vectors. With Model (packed variables) a variable is a single scalar; use lb/ub vectors to add several at once, and DictModel to add named variables.

Under the hood the variable block is registered as a variable in the box set Interval(lb, ub) (a VectorSet); see getsetvariables and add_set_variable! for the general set-based form.

NonconvexCore.chance — Method
chance(c::AbstractConstraint, scenarios; epsilon = 0.05, kappa = 10.0)

The probabilistic version of any existing constraint c: the FunctionInSet constraint P_ξ[c.f(x, ξ) ∈ setof(c)] ≥ 1 - epsilon over the user-supplied scenario batch scenarios (see ChanceSet). The classical constraints — IneqConstraint (f ≤ s), EqConstraint (f = s), SDConstraint (f ⪰ 0) — as well as any FunctionInSet — can be turned probabilistic this way.

NonconvexCore.checksubproblem! — Method
checksubproblem!(model::VecModel, optimizer; assumed = nothing,
                 hint = "", context = "the model")

Validates the features present in model against solver_capabilities of optimizer. Semantics per present feature:

  • declared true → pass;
  • declared false → ArgumentError naming the solver, the feature and a hint on how to work around it;
  • undeclared (missing or no declaration at all) → ArgumentError requiring the solver to declare the capability via solver_capabilities (strict-by-default: no opt-in).

Keyword arguments:

  • assumed: optional ConstraintCapabilities to use instead of querying the solver (for meta-algorithms that override their sub-solver's declaration),
  • hint: extra text appended to error messages,
  • context: description of the model used in error messages.
NonconvexCore.components — Method

The component sets of s: the set itself for an atomic set, the tuple of component sets for a SetProduct built from individual sets, or the vector when the product was built from a vector.

The returned function can be used in place of f in objectives and constraints; any ChainRules-compatible outer differentiation uses the prepared backend.

NonconvexCore.diffy — Function
diffy(f, x, [backend])

Returns a callable that evaluates f and differentiates through an eagerly prepared backend. See prepare_gradient and prepare_jacobian.

NonconvexCore.epigraph! — Method
epigraph!(m::AbstractModel; margin = 1.0, t_lb = -Inf, t_ub = Inf)

Reformulates the model in place into its epigraph form: the new variable t becomes the objective and the former objective f moves into the set constraint f(x) - t ∈ LessThan(0.0) (f(x) ≤ t). Minimizing t then minimizes f, and the objective bound participates in the model's FunctionInSet machinery like any other constraint. Returns the VariableInSet block of t.

NonconvexCore.nullspace_transform — Method
nullspace_transform(m::VecModel; tol = 1e-10)

Re-parameterizes the model to eliminate its linear equality constraints: with A x = b the stacked linear equalities (first-class LinearFunctions in EqualTo sets or legacy equality constraints), the substitution x = x₀ + Z y (SVD nullspace basis Z, particular solution x₀) yields an equivalent model in the reduced variables y with no linear equalities.

Everything is composed with the affine map: the objective, the remaining constraints and the box bounds — the box becomes first-class linear inequality constraints on y, and variable-in-set blocks become function-in-set constraints on y (their box parts inside the box inequalities, their cone parts composed as set constraints). Returns (reduced_model, z0, mapper) where z₀ = Zᵀ(x₀ - x_part) is the initial reduced point and mapper(z) = x_part + Z*z maps a reduced solution back to a solution of the original model (always returned; the identity when there is nothing to eliminate). Integer variables are rejected (integrality does not survive the re-parameterization).

NonconvexCore.unconstrained_transform — Method
unconstrained_transform(m::VecModel; labels = nothing)

Re-parameterizes the model so that box-constrained variables become unconstrained ones: each transformed variable with finite bounds [l, u] is replaced by zᵢ ∈ ℝ with xᵢ = l + (u - l) ⋅ logistic(zᵢ) (the TransformVariables.jl asℝ(l, u) bijection; unbounded variables pass through identically). All model functions — objective, constraints, and the box itself — are composed with the bijection, so the returned model has no bounds on the transformed variables. Set-variable cone parts (PSD-ness, the simplex sum) remain set constraints on the re-parameterized variables, and the transform/inverse ChainRules rrules keep the model differentiable under Zygote.

labels selects which variables to transform: with labels = nothing every box-bounded variable is transformed; otherwise only the entries of the VariableInSet blocks whose flags contain one of the labels are (the other variables keep their bounds unchanged).

Returns (transformed_model, z0, mapper) where z₀ = inverse(t, x₀) is the unconstrained initial point and mapper(z) = transform(t, z) maps a solution of the transformed model back to a solution of the original model (always returned; the identity when nothing is transformed). Integer variables are rejected.

NonconvexCore.JuMPEvaluator — Type
JuMPEvaluator

The derivative oracle of a JuMP model converted into a NonconvexCore model. The objective and every constraint are expressions of one MOI.Nonlinear.Model evaluated through MathOptInterface's sparse reverse-mode evaluator, so shared subexpressions are evaluated once per pass and the whole Jacobian and Lagrangian Hessian come from single evaluator calls. Affine and quadratic rows (and an affine or quadratic objective) are evaluated in closed form instead of through the evaluator, matching how JuMP itself splits such functions out of its nonlinear block; their values, Jacobians and Hessians are exact and evaluate in O(nnz).

Converted rows are exposed inequality-first (in the JuMP constraint order), then equalities (also in the JuMP constraint order). The constraints are keyed by their ConstraintIndex, because the evaluator row order is its own; the evaluator's row order is recovered from ordered_constraints.

JuMPConvertedRow

One converted constraint row of a JuMP model, in the original JuMP constraint order. Inequality rows hold sign * f(x) + shift (feasible when <= 0); equality rows hold f(x) + shift. Exactly one of ci (the row lives in the MathOptInterface Nonlinear model) and expr (the row is affine or quadratic and is evaluated in closed form) is non-nothing.
